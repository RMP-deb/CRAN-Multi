# Using this template

An R package skeleton for CRAN, following <https://r-pkgs.org>, with optional compiled
code in C++ (via 'Rcpp') and/or Rust (via 'extendr'). Pick any combination:
R only, R + C++, R + Rust, or R + C++ + Rust.
Licensed GPL (>= 3). This file and `setup.R` are build-ignored. Delete them once you're done.

## 1. Create your package

```sh
cp -r CRAN-Multi ~/code/mynewpkg        # copy the template
cd ~/code/mynewpkg
rm -rf .git                             # drop the template's own git history
Rscript setup.R mynewpkg                # R only
Rscript setup.R mynewpkg --cpp          # R + C++
Rscript setup.R mynewpkg --rust         # R + Rust
Rscript setup.R mynewpkg --cpp --rust   # R + C++ + Rust
git init
```

Run **one** of the `setup.R` lines. It deletes the files for the languages you didn't
pick, replaces `pkgname` everywhere, regenerates the Rcpp glue (if you kept C++) and
deletes itself. With `--rust` the name may only contain letters and numbers (no `.`),
because it is also the Rust crate name.

Before you pick a name, check that it's free: `pak::pkg_name_check("mynewpkg")`.

Adding a language later is easiest by copying the matching files over from a fresh copy
of this template (see the layout below) and adjusting `DESCRIPTION`.

## 2. Fill in placeholders

| File | What to change |
|---|---|
| `DESCRIPTION` | `Title`, `Description`, `Authors@R` (name, email, roles; add `comment = c(ORCID = "0000-...")` if you have one), `URL`/`BugReports` (`USERNAME`), `Depends: R (>= ...)` |
| `README.Rmd` | Goal, install, example. Render it with `devtools::build_readme()` |
| `vignettes/<name>.Rmd` | Introduction vignette (or delete `vignettes/` and the `VignetteBuilder`/knitr/rmarkdown entries) |
| `_pkgdown.yml` | `USERNAME` (or delete it if you don't use pkgdown) |
| `R/hello.R` | Example R code: replace with your own (plus its test) |
| `src/sum_squares_cpp.cpp` | Example C++ code (plus its test) |
| `src/rust/src/lib.rs` | Example Rust code (plus its test) |
| `src/rust/Cargo.toml` | Crate `version`, `rust-version` (MSRV); keep in sync with `rustc >= ...` in DESCRIPTION's `SystemRequirements` |
| `data-raw/DATASET.R` | Delete if you ship no data |

## 3. Layout

Lines marked **[C++]** or **[Rust]** only exist if you picked that language.

```
DESCRIPTION            package metadata
NAMESPACE              generated by roxygen2: don't edit by hand
LICENSE.md             full GPL-3 text (build-ignored; CRAN knows GPL-3)
NEWS.md                changelog
README.Rmd / .md       GitHub/CRAN landing page
cran-comments.md       notes for CRAN reviewers
R/                     R code
  pkgname-package.R    package docs (+ @useDynLib / @importFrom Rcpp with C++)
  RcppExports.R        [C++]  generated R wrappers for C++: don't edit by hand
  extendr-wrappers.R   [Rust] generated R wrappers for Rust: don't edit by hand
src/                   compiled code (absent for R-only packages)
  *.cpp                [C++]  your C++ source
  RcppExports.cpp      [C++]  generated glue + the package's R_init function: don't edit
  init-rust.cpp        [C++ + Rust] hooks extendr's panic handler into Rcpp's R_init
  entrypoint.c         [Rust only] C glue that registers the Rust library with R
  Makevars.in          [Rust] build template (configure turns it into Makevars)
  Makevars.win.in      [Rust] same, for Windows
  pkgname-win.def      [Rust] Windows export definitions
  rust/                [Rust]
    Cargo.toml         Rust crate manifest (dependencies go here)
    src/lib.rs         your Rust code
    document.rs        helper binary that generates R/extendr-wrappers.R
    vendor.tar.xz      vendored crates for offline CRAN builds (created at release)
configure(.win)        [Rust] run at install: checks cargo/rustc, writes src/Makevars
cleanup(.win)          [Rust] removes generated Makevars
tools/                 [Rust] config.R and msrv.R, used by configure
.vscode/               [Rust] rust-analyzer settings (build-ignored)
man/                   generated .Rd docs: don't edit by hand
tests/testthat/        unit tests (testthat 3rd edition)
vignettes/             long-form docs
inst/                  files installed as-is (create when needed: inst/CITATION, inst/extdata/)
data-raw/              scripts that build data/ (build-ignored)
.github/workflows/     R CMD check on GitHub Actions (installs Rust when needed)
```

## 4. Writing C++

* Put `.cpp` files in `src/`. Tag each function you want callable from R with
  `// [[Rcpp::export]]` on the line above it.
* Document with `//'` roxygen comments in the `.cpp` file. Add `//' @export` to make
  the function public; leave it off for internal helpers you wrap in R code.
* Run `devtools::document()` after changing signatures: it runs
  `Rcpp::compileAttributes()` and regenerates `RcppExports.*`, `NAMESPACE` and `man/`.
* `devtools::load_all()` recompiles changed files.
* Compiler flags go in `src/Makevars` (and `src/Makevars.win`), e.g.
  `PKG_CXXFLAGS = -O2`. Recent R defaults to C++17. To require a different standard,
  set `CXX_STD = CXX20` in Makevars and add `SystemRequirements: C++20` to DESCRIPTION.
  (If you also use Rust, put these lines in `src/Makevars.in` / `src/Makevars.win.in`
  instead: `src/Makevars` is generated by `configure` and git-ignored.)
* Linking to header-only libraries on CRAN (e.g. 'RcppArmadillo', 'BH'): add them to
  `LinkingTo:` (and `Imports:` if they have R functions you call).
* CRAN rules: code must compile warning-free with gcc and clang on all platforms,
  no `std::cout`/`printf` (use `Rcpp::Rcout`/`Rprintf`), no `exit()`/`abort()`,
  check for interrupts in long loops (`Rcpp::checkUserInterrupt()`), and never ship
  compiled `.o`/`.so` files.

## 5. Writing Rust

* Write functions in `src/rust/src/lib.rs` (or other modules), mark them with
  `#[extendr]` and list them in the `extendr_module!` block.
* Document with `///` comments using roxygen tags (`@param`, `@returns`, `@export`,
  `@examples`).
* Run `devtools::document()` after changing Rust code. It compiles the crate and
  regenerates `R/extendr-wrappers.R`, `NAMESPACE` and `man/`.
* Add crates with `rextendr::use_crate("serde")` or by editing `Cargo.toml`.
  Commit `src/rust/Cargo.lock`.
* `rextendr::rust_sitrep()` diagnoses toolchain problems.
* Set `NOT_CRAN=true` for faster local dev builds that don't use the vendor tarball.
  `DEBUG=true` gives a debug build.

### CRAN requirements for Rust

CRAN builds offline and has extra rules
([using_rust](https://cran.r-project.org/web/packages/using_rust.html)):

1. **Vendor dependencies** before every submission: `rextendr::vendor_crates()` writes
   `src/rust/vendor.tar.xz` (commit or at least include it in the build; keep it under
   CRAN's size limit, ~5 MB total package).
2. **Credit crate authors**: `rextendr::write_license_note()` writes `LICENSE.note`
   listing the licenses and authors of all vendored crates. Mention it in
   `cran-comments.md`, and add the Rust crate authors' copyright to `Authors@R`
   (e.g. `person("authors of the dependency Rust crates", role = "ctb", comment =
   "see LICENSE.note")`).
3. Keep `SystemRequirements: Cargo (Rust's package manager), rustc >= X` accurate:
   `configure` reports the `cargo`/`rustc` versions and fails clearly if they're missing.
4. Builds use at most 2 jobs (`-j 2`). This is already set in `tools/config.R`.
5. No compiled artifacts in the tarball (`target/` is build-ignored).

## 6. Using C++ and Rust together

A package can only have one `R_init_<pkg>()` function, and both Rcpp and extendr want to
generate one. When both are present, Rcpp's wins: `Rcpp::compileAttributes()` scans
`R/extendr-wrappers.R` for `.Call(wrap__...)` and registers the Rust routines alongside
the C++ ones in `src/RcppExports.cpp`. `src/init-rust.cpp` adds extendr's panic hook to
that init function, so `entrypoint.c` isn't needed (and `setup.R` removes it).

One consequence: Rcpp only sees a new Rust function after the wrappers are regenerated.
**When you add, remove or rename a Rust function, run:**

```r
devtools::document()        # compiles Rust, rewrites R/extendr-wrappers.R
Rcpp::compileAttributes()   # registers the new set of wrap__* routines
devtools::document()        # recompiles with the updated registration
```

Signs you forgot: `object 'wrap__foo' not found` (added) or
`undefined symbol: wrap__foo` (removed). Changes inside existing Rust functions only
need the usual single `devtools::document()` / `load_all()`.

Keep exported names distinct across languages (e.g. not `foo()` in both C++ and Rust).

## 7. Daily workflow

```r
devtools::load_all()     # Ctrl+Shift+L
devtools::document()     # Ctrl+Shift+D: regenerate NAMESPACE, man/ and compiled-code glue
devtools::test()         # Ctrl+Shift+T
devtools::check()        # Ctrl+Shift+E: full R CMD check
usethis::use_r("foo")    # new R/foo.R
usethis::use_test("foo") # new tests/testthat/test-foo.R
usethis::use_package("dplyr")  # add to Imports
```

## 8. Releasing to CRAN

`usethis::use_release_issue()` creates the full checklist. The core steps:

1. `usethis::use_version("minor")`: drop the `.9000` (e.g. `0.1.0`)
2. [Rust] `rextendr::vendor_crates()` and `rextendr::write_license_note()` (see above)
3. `urlchecker::url_check()`, `devtools::spell_check()`
4. `devtools::check(remote = TRUE, manual = TRUE)`: aim for 0 errors, 0 warnings, 0 notes
5. `devtools::check_win_devel()`, `rhub::rhub_check()`
6. Update `cran-comments.md` and `NEWS.md`
7. `devtools::submit_cran()`
8. After acceptance: `usethis::use_github_release()` and `usethis::use_dev_version()`

Common CRAN reviewer requests: put software names in single quotes in Title/Description,
document `@returns` for every exported function, don't write to the user's home dir,
use `\donttest{}` (not `\dontrun{}`) for slow examples, and keep examples under ~5s.
